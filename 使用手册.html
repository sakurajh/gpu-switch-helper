4

提交作业（核心）

⚠ 语法注意：调度系统使用 #JSUB 指令，严禁使用 SLURM / SGE / PBS 语法。

方式一：命令行提交

命令格式
jsub -n <CPU核数> -gpgpu <GPU数量> -q <队列名> -J <作业名> -o <输出> -e <错误> ./commandline
参数含义
-n <CPU数>申请 CPU 核数，不能超过队列限制
-gpgpu <GPU数>申请的 GPU 数量
-q <队列名>指定队列，资源不足时排队、满足时派发；用 jqueues -u <账户> 确认权限
-J <作业名>作业名，方便辨识
-o <输出>调度系统输出；%J 表示作业号，如 -o output.%J
-e <错误>可执行文件运行时的错误输出

示例（10 核 + cpu_x86 队列 + python 打印 hello world）：

示例
jsub -n 10 -q cpu_x86 -J test -o test.log "python3 helloworld.py"

方式二：脚本提交（推荐）

submit.sh — 标准格式
#!/bin/bash
#JSUB -q gpu_4090     # 队列
#JSUB -gpgpu 1        # GPU 卡数
#JSUB -n 8            # CPU 核心数
#JSUB -e error.%J     # 错误日志（%J=作业号）
#JSUB -o output.%J    # 状态日志
#JSUB -W 48:00        # 运行时间限制
#JSUB -J my_job       # 作业名称

module purge
module load APP_MODULE_FILE
mpirun APP_EXEC [-i input.file] [-o output.file] [...]
提交脚本
jsub < submit.sh    # 标准输入方式
jsub ./submit.sh    # 直接传脚本文件

脚本编写检查清单

  1. 是否查阅了对应作业类型的文档？（串行/GPU/MPI 见参考文档，勿凭经验假设参数）
  2. 队列名是否用 jqueues 确认存在？（没有 "default" 队列）
  3. module load 前是否加了 module purge？
  4. 是否在 -R 中指定 select[type==LINUX64]？
  5. MPI 作业是否从 JH_HOSTS 生成 hostfile 并计算 NP？
  6. 是否用 { ... } > logfile 2>&1 显式重定向输出？
  7. 脚本是否 chmod +x？
注意：① Windows 编写的脚本需转码：dos2unix <脚本名>；② 确保脚本有执行权限 chmod +x。

jsub 选项速查（对照 SLURM）

JSUB 选项说明SLURM 对应
-J name作业名--job-name
-n N总处理器数--ntasks
-R "select[...] span[...]"资源需求--constraint
-q queue队列--partition
-m node指定节点/节点组--nodelist
-o / -e file输出 / 错误文件--output / --error
-W minutes运行时限--time
-M MB内存限制--mem
-gpgpu NGPU 数--gres=gpu:N
-x / -ux独占 / 用户独占节点—
-Is / -IX / -I交互式（服务/X11/普通）--interactive
-w 'status(job)...'作业依赖（V6.4+）--dependency
提示：命令行选项会覆盖脚本中指定的选项。

-R 资源需求详解

关键字作用示例
select节点选择条件select[mem>1024] · select[type==LINUX64]
rusage资源预留rusage[mem=500] · rusage[mem=800/slot]
span分布控制span[hosts=1]（单节点）· span[ptile=2]

rusage 预留方式：

写法含义
mem=800默认按 slot 预留（等同 mem=800/slot）
mem=800/slot预留值 × 节点分配的 slot 数
mem=800/host每节点固定预留，不乘 slot 数
组合示例
# 选 LINUX64 节点 + 预留 500MB + 单节点
jsub -n 4 -R "select[type==LINUX64] rusage[mem=500] span[hosts=1]" my_job

# 内存充足节点 + 每节点 2 slots
jsub -n 8 -R "select[mem>1024] rusage[mem=800] span[ptile=2]" my_job

多卡 GPU 作业（4 × H800 示例）

选型说明：平台 GPU 队列为 gpu_4090gpu_a800gpu_h800gpu_6000ada，没有 H100 队列。H800 是 H100 的国内版（同为 Hopper 架构），大模型训练请选 gpu_h800 队列。
submit_gpu4.sh — 单机 4 卡 DDP
#!/bin/bash
#JSUB -J multi_gpu_train
#JSUB -q gpu_h800      # H800 队列
#JSUB -gpgpu 4         # 申请 4 张卡
#JSUB -n 32            # 配套 CPU 核数
#JSUB -e error.%J
#JSUB -o output.%J

source activate myenv
torchrun --nproc_per_node=4 train.py   # PyTorch DDP 单机 4 卡

进阶：-gpgpu 支持按型号/显存/MIG 精细申请，语法 -gpgpu "num [type=...] [vendor=...] [gmem=...] [sm=num] [mig=gsize]"：

精细申请示例
# 4 张卡，每卡预留 40GB 显存（型号字符串以 jhosts attrib -l 查询为准）
jsub -q gpu_h800 -gpgpu "4 gmem=40000" -n 32 ./train_gpu4.sh

# 请求 1 个 MIG 切分实例（如 A100）
jsub -gpgpu "1 mig=7" my_job
子参数含义
numGPU 卡数量（必须）
type指定 GPU 型号，多个型号逗号分隔
vendor指定厂商（如 nvidia）
gmem每卡预留显存大小（MB）
sm指定 SM（流处理器）数量
migMIG 实例规格（1/2/3/4/7）
多卡注意事项：① 配额：用 jlimits -n 确认 GPU 配额，配额满则排队；② 节点卡数：用 jhosts attrib -l <节点名> 看 ngpus 字段；③ 4090/6000Ada 无 NVLink（走 PCIe），大模型训练优先 A800/H800；④ 跨节点多机多卡需用 JH_HOSTS 构造节点列表 + torchrun/NCCL，建议先小规模测试或咨询管理员。

MPI 并行作业

参数说明
-n <N>总进程数
-R "select[type==LINUX64] span[ptile=N]"节点类型 + 每节点进程数（必须指定节点类型，否则可能分到 view 节点导致失败）
-m <节点/节点组>指定节点或节点组

节点数 = 总进程数 ÷ 每节点进程数。例：-n 16 -R "...span[ptile=4]" → 4 节点 × 4 进程。

从 JH_HOSTS 生成 hostfile

JH_HOSTS 格式：节点名1 slot数1 节点名2 slot数2 ...（1 slot = 1 CPU 核）。

Intel MPI / MPICH
HOSTFILE="hostfile_${JH_JOBID}"
echo "$JH_HOSTS" | awk '{for(i=1;i<=NF;i+=2){host=$i;slots=$(i+1);for(j=1;j<=slots;j++) print host}}' > "$HOSTFILE"

NP=$(echo "$JH_HOSTS" | awk '{s=0; for(i=2;i<=NF;i+=2) s+=$i; print s}')
mpirun -n "$NP" -machinefile "$HOSTFILE" ./my_program input.dat
OpenMPI
HOSTFILE="hostfile_${JH_JOBID}"
echo "$JH_HOSTS" | awk '{for(i=1;i<=NF;i+=2) printf "%s slots=%s\n", $i, $(i+1)}' > "$HOSTFILE"

NP=$(echo "$JH_HOSTS" | awk '{s=0; for(i=2;i<=NF;i+=2) s+=$i; print s}')
mpirun -np "$NP" --hostfile "$HOSTFILE" -x PATH -x LD_LIBRARY_PATH --bind-to core ./my_program input.dat
⚠ OpenMPI：默认不把当前环境变量传给 MPI 进程，必须用 -x VAR 显式传递（-x 后必须跟变量名）。module load 设置的 PATH/LD_LIBRARY_PATH 需通过 -x 传递。

常见问题 FAQ

问题原因 / 解决方法
提交失败，无作业号作业命令或脚本参数有错误，修改错误参数
一直排队不计算集群空闲 CPU/GPU 不足，或用户达配额上限。等资源释放，或取消作业、减少申请量；用 jlimits 确认配额
缺少系统库文件缺 lib*：未设 LD_LIBRARY_PATH 或系统无该库（联系管理员）；缺/不兼容 cudnn.x：加载正确版本的 cuda 环境
脚本编码问题Windows 编辑的脚本需转码：dos2unix <脚本名>
作业运行失败（EXIT）查看标准输出/错误输出分析。用 -o output.log（标准输出）、-e error.log（标准错误）
权限问题日志提示 Permission denied：程序或其子程序无执行权限，用 chmod +x <app>
Linux 桌面打不开不要在 .bashrc 添加 conda 环境变量（破坏系统环境）。需 conda 时先开桌面再激活
